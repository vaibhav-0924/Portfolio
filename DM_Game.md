**Case Study: Buildra**

| Section          | Content                                                                                                                                       |

| **Problem**      | Developers spend hours scaffolding new projects. Existing tools generate boilerplate but not functional, context-aware code.                  |

| **Architecture** | User prompt → Gemini AI agent loop → Inngest event pipeline (generate → validate → correct) → E2B sandbox execution → SSE streaming to client |

| **Challenge**    | AI-generated code frequently contains errors. Built a self-correcting loop that feeds error output back to the LLM.                           |

| **Result**       | Working platform that generates functional Next.js apps from natural language descriptions with live preview.                                 |
| **Lesson**       | Event-driven architectures (Inngest) make AI agent loops significantly more reliable than raw promise chains.                                 |

# PART 5 — CONTENT INTEGRITY & GENERATION SYSTEM

> This section defines the rules, filters, and workflows that govern all content creation across X, LinkedIn, portfolio, resume, and DMs.

---

## 5.1 Content Honesty Filter

Before any content goes public, answer these five questions:

### 1. Did this actually happen?

If no → reject.

### 2. Did I actually build or understand it?

If no → reframe as exploration/investigation, not expertise.

### 3. Can I prove the claim?

If no → weaken or remove the claim.

### 4. Does this accurately represent my current capability?

If no → rewrite to match actual level.

### 5. Could I defend this claim if a strong engineer asked follow-up questions?

If no → don't publish it as expertise.

---

## 5.2 Automatic Rejection Rules

Reject drafts containing unsupported claims such as:

| Banned Phrase | Reason |
| --- | --- |
| production-grade | Implies production deployment and validation |
| enterprise-grade | Implies enterprise usage |
| highly scalable | Implies load testing and scaling evidence |
| highly performant | Implies benchmarking evidence |
| production-ready | Implies deployment readiness validation |
| industry-leading | Implies competitive analysis |
| expert | Implies deep mastery |
| mastered | Implies complete understanding |
| fault-tolerant | Implies failure mode testing |
| optimized | Implies benchmarking and profiling |
| distributed system | Implies actual distributed deployment (unless describing architecture study) |

Also reject:

- Fake metrics
- Invented users
- Invented scale
- Invented business results
- Invented deployments
- Invented professional experience

> [!CAUTION]
> These rules apply to ALL content: DMs, cover letters, posts, portfolio descriptions, resume bullet points, and interview answers.

---

## 5.3 Content Generation Rules

When generating content, distinguish between these capability levels:

| Level | Meaning | Example |
| --- | --- | --- |
| **Used** | I used the technology | "I used Prisma for database access" |
| **Explored** | I studied or experimented with it | "I explored how tRPC handles type inference" |
| **Built** | I implemented it | "I built the auth system with raw SQL" |
| **Understood** | I can explain the important mechanisms | "I understand how Inngest orchestrates multi-step pipelines" |
| **Mastered** | I can independently design, implement, debug, and reason about it deeply | Use very sparingly |

> [!WARNING]
> The content generator must NEVER automatically upgrade "Used" into "Built" or "Built" into "Mastered."
